# 엔지니어 로그

수락된 spec으로 구현 계획을 세우는 동안, spec이 정하지도 묻지도 않아서 혼자 정해야 했던 것을 한 줄에 하나씩 적습니다. 엔지니어마다 한 부씩 씁니다.

- spec:
- 수락한 날과 수락한 사람:
- 기록한 사람 (역할):
- 기록 기간: 수락한 날부터 계획을 마친 날까지 (____ ~ ____)

## 무엇을 적나요

spec만 보고는 알 수 없어서 내가 정했거나 누군가에게 물어봐야 했던 것:
- 어떤 상황에서 제품이 어떻게 동작하는지
- 사람에게 무엇을 보여 주거나 알리는지
- 숫자, 한도, 날짜, 조건
- 정책을 어떻게 적용하는지

이런 것도 적습니다.
- 물어봐서 해결한 것. spec에 있었어야 할 것이기 때문입니다.
- spec에 있는지 확신이 없는 것. 회고 때 가립니다.
- spec이 열린 질문으로 남겨 둔 것은 빼되, 그 질문에 계획에 필요한 것이 빠져 있었다면 적습니다.

적지 않습니다: 코드 구조, 저장 방식, 스키마, 재시도 간격, 테스트 구성처럼 엔지니어가 아닌 누구도 차이를 알아채지 못하는 선택.

정할 것이 하나도 없었다면 표에 "없음"이라고 적어 주세요. 빈 표와 "없음"은 다른 결과입니다. 계획을 마친 뒤 구현 중에 찾은 것은 '정해야 했던 것' 앞에 "(구현 중)"이라고 붙여 같은 표에 적어도 됩니다.

## 열 설명

- **정해야 했던 것:** 한두 문장. 구체적인 날짜나 금액을 예로 들면 좋습니다.
- **spec에서 나온 곳:** 섹션 이름과 단계, 규칙(R), 사례, 질문(Q) 번호. spec에 아무 단서가 없으면 "없음"이라고 쓰고, 어느 흐름에서 생겼는지 적습니다.
- **어떻게 했나:** "혼자 정함: 무엇으로" / "물어봄: 누구에게, 답까지 며칠" / "보류".
- **누가 정했어야 하나:** 원 작성자, 제품 책임자, 정책 소유자(어느 정책), 기술 리드, 엔지니어, 모르겠음.
- **돈 / 개인정보 / 법적 의무:** 해당하는 것을 모두, 없으면 "없음".
  - 돈: 금액, 결제, 환불, 수수료, 정산
  - 개인정보: 사람을 알아볼 수 있는 정보를 모으거나, 보여 주거나, 보관하거나, 지우는 일
  - 법적 의무: 고지, 동의, 보관 기간, 계약, 규제
- **회고 분류:** 엔지니어는 비워 둡니다. 회고 전에 진행자가 기술 리드, 제품 책임자와 함께 채웁니다.
  - 진짜 빈틈: spec이 정하지도 묻지도 않았고, 엔지니어가 아닌 누군가가 정했어야 함. 종류도 적습니다: 누가 해당하나 / 경계(이상·초과, 반올림, 날짜 세기, 시간대) / 이전 이력 / 다른 기록에서 가져오는 값 / 시점과 상태 / 반복 / 실패 / 사람에게 알리는 것 / 남는 기록 / 범위 경계 / 그 밖
  - spec에 있었음: spec이 이미 정했거나 물었음. 어디에 있었는지 적습니다.
  - 엔지니어링 선택: 엔지니어가 아닌 누구도 알아채지 못함
